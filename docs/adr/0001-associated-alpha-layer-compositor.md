# Treat CanvasGroup and Sprite2D as associated-alpha Layers

The RD Layer renderer resolves each Layer to associated alpha, selects the node's runtime blend override through the existing canvas pipeline cache, and resolves sibling Clipping Stacks in reusable nested scratch targets before applying the Base's blend mode. Multiply requires dual-source blending on Vulkan and Metal; this keeps custom canvas shaders reusable, preserves the Base alpha for Photoshop-style clipping, and avoids a destination-reading composition pass for each Layer.

For a Composite `CanvasGroup`, `_mark_layer_stacks` derives Clipping Base and Clipped Layer relationships from direct `child_items` in scene-tree sibling index order. Normal CanvasItem ordering can make the rendered order diverge from that sequence when `y_sort_enabled = true`, or when a child Layer uses a nonzero `z_index`, `z_as_relative = false`, or `show_behind_parent = true`; `top_level = true` can remove the child from the parent's item list entirely. The renderer intentionally does not reconcile these orderings. Supported child Layers therefore require `z_index = 0`, `z_as_relative = true`, `show_behind_parent = false`, and `top_level = false`, while their Composite `CanvasGroup` parent requires `y_sort_enabled = false`. Violations emit a clear error; rendering for the affected subtree is undefined, but the engine must not crash.
